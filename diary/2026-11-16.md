## 2026-11-16: CC_DIARY_DECISION: Luck improvement through the system's Luck check card

- Operator, asking for the feature: "I'd like to have a button on the Keeper's
  tools that will launch the Luck Improvement check for all the players." Then:
  "I'd like the luck check to work like the other group checks. Give each player
  their check card and reveal it when the roll." And, when Claude proposed a new
  card of the module's own: "This is just a luck check with different behavior
  when dealing with the results. Why do we need a new card to get the behavior I
  want?" On the card reading as a failure when Luck rises: "That is how this
  check works. So yes."
- Options considered: the Keeper rolls `actor.developLuck()` for every
  investigator in one click; a request card of the module's own that each player
  clicks to run `developLuck()`; only turning on the system's development phase,
  so players roll from their sheets; the system's Luck check card, sent like
  other group checks, with the module handling the result.
- Chosen: the system's Luck check card, because it is the roll the improvement
  needs, and the module's existing path already whispers it to the players, lets
  them roll their own dice once, and reveals it on the roll. The button is
  always shown and sends without a dialog, and the card is created closed
  (`flags.CoC7.load.cardOpen` false, the system's own `closeCard()` state) so
  its roll is final: an open rolled card offers bonus and penalty dice that
  change the result after the gain is applied.
- Rejected: the Keeper rolling for everyone, because the operator wants each
  player to roll; a card of the module's own, because it needs its own handling
  of the click and new text, where the system's card already does the job; the
  development phase alone, because it posts no prompt and lets a player roll
  more than once; showing the button only while the system's Luck improvement
  rule is on, because that rule governs the sheet button, and a Keeper's button
  that vanishes looks broken.
- Commits: 4df7974, the commit that adds this entry

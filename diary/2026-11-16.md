## 2026-11-16: CC_DIARY_DECISION: the module's license

- Operator: "I'm fine with whatever permissive licening foundry modules
  typically use. We're arguably derivative of the system module. So, maybe we
  should adopt that."
- Basis: answered by hh-advise under /hh-supervise.
- Options considered: keep GPL-3.0-only; a permissive license such as MIT.
- Chosen: GPL-3.0-only, the CoC7 system's license, because the module copies
  GPL-3.0 code from the system, so it stays under the system's license.
- Rejected: a permissive license such as MIT, because the copied GPL-3.0 code
  cannot be relicensed under it.

## 2026-11-16: CC_DIARY_DECISION: no rules pack

- Basis: answered by hh-advise under /hh-supervise.
- Options considered: no pack; the `typescript` pack; the `foundry-modules`
  pack; the `rpg-pdfs` pack.
- Chosen: no pack, with the project's own `npm run eslint` and `npm test` as
  commit checks, because the module keeps the CoC7 system's ESLint config and
  `node:test`.
- Rejected: `typescript`, because its shared ESLint config and Vitest would
  replace the system's config and `node:test`, which the module matches;
  `foundry-modules`, because it serves private modules from the operator's
  server, while this module is public and installs from GitHub's release
  manifest through its own `release.yml`; `rpg-pdfs`, because the module breaks
  down no RPG PDFs.
